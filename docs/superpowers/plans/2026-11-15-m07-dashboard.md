# M07 Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a usable Dashboard for Todo management, weekly history, Pomodoro configuration, profile/ledger, and persisted Settings.

**Architecture:** WPF feature ViewModels consume existing Core services and narrow read-query ports; they never receive `AppDbContext`. SQLite implements profile, ledger, history, and versioned JSON Settings reads. `MainWindow` remains the single shell and swaps feature views through one `DashboardViewModel`.

**Tech Stack:** .NET 10, WPF, EF Core 10, SQLite, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-11-easy-to-do-list-design.md`; milestone acceptance in `TASKS.md` M07.

## Global Constraints

- Windows 11 x64 MVP, offline and local-first.
- Core remains independent of WPF, EF Core, database, and system clock implementations.
- Todo/reward mutations continue through `ITodoService` transactions; UI never edits EF entities directly.
- Dashboard uses the committed Guild Quest Board tokens from `DESIGN.md`.
- M07 does not implement compact Overlay controls, animation/combo/Undo presentation, native tray, notifications, or auto-start registration.

## Review Focus

- Corrupt or unsupported Settings JSON returns defaults without modifying the stored payload.
- Repeated Save commands do not create multiple Settings rows.
- Todo form rejects blank title and deadline before start with field-specific Vietnamese messages.
- Loading or mutation failure leaves existing UI data intact and exposes a recoverable error message.
- Profile and ledger reload after Todo completion/cancellation so totals do not remain stale.
